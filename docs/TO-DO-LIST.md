## 항목 상세

### 9. 실제 경기 명장면 프리셋 (StatsBomb OpenData)

- **내용**: 원래 원했던 "실제 경기 분석"의 부분 실현. StatsBomb OpenData(무료, GitHub 공개)의 이벤트 데이터에는 슈팅 순간 양 팀 전원의 실제 좌표(freeze frame)가 담겨 있어, 이를 국면 프리셋으로 변환하면 "2022 월드컵 결승 결승골 장면" 같은 실제 배치를 불러올 수 있음.
- **제약 (중요)**: 슈팅 장면 위주(전 경기 트래킹 아님), 좌표계 변환(StatsBomb는 0~120 × 0~80) 필요, 원본 JSON이 커서 사전 가공 스크립트 필요. 작업량 중~대.
- **연혁**: "실제 경기를 DB에서 검색해 자동 분석"은 2026-09-01 무료 API가 국면별 선수 좌표를 제공하지 않아 기각 → 감독 프리셋으로 대체. 이 항목은 그 대안의 확장.
- **착수 전 확인(2026-09-09)**: 실제로 StatsBomb 오픈 데이터(GitHub `statsbomb/open-data`)를 조사해보니, 슛의 "프리즈프레임"(그 순간 선수 좌표)이 슛에 관여된 선수만 담고 있어(예: 2022 월드컵 결승 음바페 80분 동점골도 11명뿐, 양 팀 22명 전원이 아님) 이 앱의 스키마가 요구하는 11v11을 다 채울 수 없다는 걸 확인. 사용자에게 확인 질문 후 **"실제 좌표(추적된 선수) + 그 시점 포메이션 템플릿(안 잡힌 선수)으로 보완"** 방식으로 결정.
- **구현**:
  - 사전 조사·가공은 파이썬 스크립트로 일회성 수행(런타임에 API를 호출하는 게 아니라 감독 프리셋과 같은 "정적 JSON 파일" 방식) — StatsBomb 공개 GitHub 저장소의 `competitions.json`/`matches/`/`events/`/`lineups/` raw JSON을 직접 fetch해 리서치.
  - **좌표 변환**: StatsBomb는 x 0~120(항상 공격 방향), y 0~80(폭) — 이 앱은 x 0~100(폭), y 0~100(0=상대 골문/공격 방향, 100=자팀 골문). `app_x = sb_y/80*100`, `app_y = 100 - sb_x/120*100`.
  - **선정 장면**: 2022 카타르 월드컵 결승(아르헨티나 vs 프랑스) 80분, 음바페의 발리 동점골(3-2→3-3). `lineups.json`의 포지션 시간창(from/to)으로 그 순간 그라운드 위 22명 전원과 각자 역할을 정확히 산출한 뒤, 프리즈프레임에 실제 추적된 11명(프랑스 4명 — 슈터 음바페 포함, 아르헨티나 8명 — 아르헨티나가 슛을 막는 쪽이라 더 많이 잡힘)은 그 좌표 그대로, 나머지 11명(프랑스 7명, 아르헨티나 3명)은 그 시점 확인된 포메이션(프랑스 4-4-2, 아르헨티나 4-3-3 — `tactics` 이벤트로 확인)의 기존 `lib/formations.ts` 템플릿 슬롯에 역할별로 배치. 어시스트(튀랑→음바페 패스)와 슛 궤적도 실제 좌표로 `pass`/`run` 화살표 추가, 골 시점을 타임라인 체인징 포인트(80분, "음바페 동점골")로도 등록.
  - StatsBomb 라이선스가 "데이터 출처를 StatsBomb으로 명시" 요구 — summary·블러브 문구에 "StatsBomb 오픈 데이터" 명시로 충족(로고 게재는 개인/로컬 프로젝트 범위상 생략).
  - 새 `public/samples/matches/mbappe-wc2022-final.json`(감독 프리셋과 같은 zod 스키마 검증 대상 — `samples.test.ts`가 디렉터리를 재귀 스캔해서 자동으로 포함됨), 새 `components/editor/MatchPresetPicker.tsx`(`ManagerPresetPicker`와 같은 카드 그리드 UI, 로더 함수는 `handleSelectPreset`로 감독 프리셋과 공유), `NewAnalysisPage.tsx`에 "실제 경기 명장면으로 시작하기" 섹션 신설.
- **검증**: `tsc --noEmit`/`eslint`/`vitest run`(`samples.test.ts`가 새 프리셋도 자동 검증, 150 tests 통과)/`npm run build` 통과. 처음엔 `pressingLineY: null`을 명시적으로 넣어서 zod 검증 실패(스키마는 `undefined`를 기대, `null` 아님) — 필드를 아예 생략하도록 수정해 통과. Playwright로 실제 브라우저 확인: `/new`에 새 섹션·카드 렌더링 → 클릭 시 정상 로드 → 팀명(아르헨티나/프랑스)·매치명·요약 텍스트 정상 → 타임라인에 "80'" 위치에 체인징 포인트 점 정확히 표시 → 스크린샷으로 실제 배치 육안 확인(프랑스 공격수 4명이 골문 앞에 밀집, 아르헨티나 수비진이 그 앞에서 스크램블하는 모양이 실제 골 장면과 일치, 슛 궤적 화살표도 보임).
