## 항목 상세

### 3. 감독 프리셋 추가

- **내용**: 후보 — 무리뉴, 안첼로티, 투헬, 포체티노 등 + K리그 감독. `frontend/public/samples/managers/`에 JSON 추가 + `ManagerPresetPicker` 배열 등록이 전부.
- **유의**: 좌표는 공개 전술 분석 기반 재구성(실제 트래킹 아님) — 기존 프리셋과 같은 주석 유지. 감독 최신 이력(해임·이적)은 추가 시점에 다시 확인한다.
- **사용자 요청(2026-09-07)**: "3번 감독 프리셋 추가하자"
- **구현**: 무리뉴·안첼로티·투헬 3명 추가(`mourinho.json`/`ancelotti.json`/`tuchel.json`). 지식 컷오프(2026-01) 이후 이적 가능성이 있어 착수 전 웹 조사 에이전트 3개를 병렬로 띄워 각자 현재 소속·실제 선발 라인업을 교차 확인 — 셋 다 지식 컷오프 이후 새 자리로 이동한 상태였다(무리뉴→레알 마드리드, 안첼로티→브라질 대표팀, 투헬→잉글랜드 대표팀, 둘 다 2026 월드컵 감독). 실제 확정 선발 XI·등번호를 기반으로 국면별 좌표를 재구성했고, 투헬 프리셋은 국면마다 포메이션이 크게 바뀌는 특징(공격 시 풀백 인버트로 사실상 3-2-5, 비보유 시 4-4-2)까지 좌표만으로 표현했다. `formation` 필드는 국면 내내 고정값(기존 프리셋들과 동일한 방식)이며 시각적 형태 변화는 좌표 이동만으로 구현.
- **검증**: `tsc --noEmit`/`eslint --max-warnings 0`(기존 경고 2건은 이번 변경과 무관)/`vitest run`(신규 3개 파일 모두 `samples.test.ts` zod 스키마 통과, 119 tests) 통과. `npm run build` 성공. vite 재기동 후 Playwright로 `/new`에서 3개 프리셋 모두 로드해 스크린샷 확인 — 포메이션 모양·등번호·포지션 라벨·패스 체인 연결·런 화살표 전부 의도대로 렌더링됨(기존 프리셋 대비 동일한 ellipse 개수로 렌더링 정상 확인).

### 7. 분석 목록 고도화

- **내용**: 목록 화면에 썸네일 미리보기(base 국면 미니 렌더링), 제목·날짜 검색, 태그. 목록이 수십 개가 되면 필요.
- **기술 메모**: 썸네일은 저장 시점에 base 국면을 작은 PNG로 만들어 두는 방식(목록 조회 시 렌더링은 느림) — 백엔드에 파일 또는 BLOB 컬럼 필요.

### 9. 실제 경기 명장면 프리셋 (StatsBomb OpenData)

- **내용**: 원래 원했던 "실제 경기 분석"의 부분 실현. StatsBomb OpenData(무료, GitHub 공개)의 이벤트 데이터에는 슈팅 순간 양 팀 전원의 실제 좌표(freeze frame)가 담겨 있어, 이를 국면 프리셋으로 변환하면 "2022 월드컵 결승 결승골 장면" 같은 실제 배치를 불러올 수 있음.
- **제약 (중요)**: 슈팅 장면 위주(전 경기 트래킹 아님), 좌표계 변환(StatsBomb는 0~120 × 0~80) 필요, 원본 JSON이 커서 사전 가공 스크립트 필요. 작업량 중~대.
- **연혁**: "실제 경기를 DB에서 검색해 자동 분석"은 2026-09-01 무료 API가 국면별 선수 좌표를 제공하지 않아 기각 → 감독 프리셋으로 대체. 이 항목은 그 대안의 확장.

### 10. 배포 (Docker)

- **내용**: 저장소 루트의 `Dockerfile`/`docker-compose.yml`(백엔드 이미지 + `./data` 볼륨 마운트)은 이미 존재. 남은 결정: 프론트 빌드 산출물을 백엔드 이미지에 정적 서빙으로 포함할지 별도로 둘지.
- **기술 메모**: 컨테이너에서 `npm run build` → FastAPI가 `dist/`를 StaticFiles로 서빙하는 단일 이미지 구성이 가장 단순. 개발은 계속 로컬 2프로세스.
- **사용자 결정(2026-09-09)**: "단일 이미지로 가자" — 프론트 빌드 산출물을 백엔드 이미지 안에 정적 서빙으로 포함하는 쪽으로 확정(별도 nginx 서비스로 분리하는 안은 채택 안 함).
- **구현**:
  - `Dockerfile`을 멀티스테이지로 변경 — 1단계(`node:20-slim`)에서 `npm ci && npm run build`(이때 `VITE_API_BASE_URL=/api`로 빌드해 배포 시엔 상대 경로를 쓰게 함 — 로컬 개발 `.env`의 절대 URL과는 별개), 2단계(기존 `python:3.11-slim`)로 `frontend/dist`만 복사. 컨테이너 안 경로는 `/app/frontend/dist`, `config.py`의 기존 `PROJECT_ROOT`를 그대로 재사용해 `/app/backend`와 나란히 오도록 맞춤.
  - `backend/main.py`에 정적 서빙 추가 — `/assets`는 `StaticFiles`로 마운트, 그 외 모든 경로는 `/{full_path:path}` 캐치올 라우트가 받아 실제 파일(예: `/samples/managers/*.json`, 파비콘)이면 그대로 서빙하고 없으면 `index.html`로 폴백해 React Router가 새로고침에도 살아남게 함. `/api/*` 라우트보다 뒤에 등록해 우선순위가 API에 있도록 함. **`FRONTEND_DIST.is_dir()`로 감싸 로컬 개발(2프로세스, `frontend/dist` 없음)에는 이 블록 전체가 조용히 비활성화** — CLAUDE.md의 "프론트는 컨테이너에 넣지 않고 로컬 Vite로 개발" 원칙을 건드리지 않음.
  - `docker-compose.yml`은 프론트·백엔드가 같은 오리진이 됐다는 점만 주석으로 반영(`CORS_ORIGINS`는 "로컬 Vite를 프론트로 쓰면서 이 컨테이너를 API로만 붙이는 경우"를 위해 그대로 둠).
- **검증**: 실제로 `docker build`로 이미지를 빌드하고 컨테이너를 띄워 확인 — `/api/health` 200, `/`와 `/new`(클라이언트 라우트) 둘 다 `index.html` 반환, `/assets/index-*.js`·`/assets/index-*.css`·`/samples/managers/guardiola.json` 전부 200, 빌드된 JS 번들 안에 `"/api"`(상대 경로)만 있고 로컬 개발용 `localhost:8000` 절대 URL은 없음을 확인. `POST /api/analyses`로 분석을 만들고 호스트에 바인드 마운트한 `./data/tacticore.db`에 실제로 저장되는지, `GET /api/analyses`로 다시 읽히는지 확인. Playwright로 실제 브라우저에서 `http://localhost:8199`(컨테이너 포트)에 접속해 감독 프리셋 로드·홈 화면의 "최근 작업" 목록(방금 만든 분석이 보임)까지 콘솔 에러 없이 확인. 로컬 개발 backend가 이 변경으로 영향받지 않는지도 확인(빌드 검증 중 남은 `frontend/dist` 잔여물을 지워 로컬 2프로세스 개발 환경이 실수로 정적 서빙 모드로 전환되지 않게 함).

### 11. 로그인/계정

- **내용**: 분석 목록을 사용자별로 분리. 로컬 1인용인 동안은 의미가 제한적이라 배포 이후로 미룸.
- **사용자 요청(2026-09-09)**: "이메일/비밀번호로 하자" — 소셜 로그인·매직링크는 채택 안 함.
- **사용자 결정(2026-09-09)**:
  - 로그인 도입 전에 쌓인 기존 분석(주인 없음)은 **처음 가입하는 계정에 전부 귀속**.
  - **비로그인 상태에서도 편집기는 그대로 사용 가능** — 저장/목록만 로그인 필요(기존 "서버 미기동" 폴백과 같은 철학).
- **구현**:
  - 백엔드: `models.User`/`models.Session`(세션 테이블 방식 — JWT 대신 택한 이유는 로그아웃 시 즉시 무효화가 필요해서), `Analysis.user_id`(FK, 기존 테이블이라 `main.py`의 `_ensure_column`으로 마이그레이션). `auth.py`(bcrypt 해시·세션 생성/파기·`get_current_user` 의존성), `routers/auth.py`(`/api/auth/register|login|logout|me`, httpOnly 쿠키 `tacticore_session`, 30일). 회원가입 시 `db.query(models.User).count() == 1`이면 주인 없는 분석 전부를 그 계정에 UPDATE — 사용자 결정 그대로 구현.
  - `routers/analyses.py`: 목록·생성·수정·삭제는 `auth.get_current_user` 필수 + 수정/삭제는 소유자 본인 확인(403). **`GET /api/analyses/:id`(단건 조회)는 그대로 완전 공개** — 공유 링크(8번, `/share/:id`)가 이 엔드포인트에 의존하므로 로그인 도입 후에도 깨지지 않게 유지.
  - `main.py`: CORS `allow_credentials=True`로 변경(세션 쿠키 필요, `allow_origins`는 이미 명시적 목록이라 스펙 충족).
  - 이메일 형식 검증은 `pydantic[email]`을 새로 안 들이려고 정규식으로만 확인(실존 여부 확인용 메일 발송 인프라 없음 — 범위 밖).
  - 프론트: `lib/api.ts`(`credentials: 'include'` + `/auth/*` 함수), `hooks/useAuth.ts`(React Query — `useServerHealth`와 같은 패턴), `routes/LoginPage.tsx`/`RegisterPage.tsx`, `App.tsx` 헤더에 로그인 상태 표시, `SaveButton`/`DuplicateButton`은 서버 미기동뿐 아니라 비로그인도 비활성화 사유로 표시, `AnalysesPage`/`RecentAnalyses`는 비로그인 시 목록 대신 로그인 안내.
- **검증**: 백엔드 `py_compile` 통과. 실제 로컬 백엔드(`uvicorn --reload`)에 curl로 register→me→list(200, 27건)→list without cookie(401)→get single analysis without cookie(200, 공개 유지 확인)→logout→me(401) 확인. 프론트 `tsc --noEmit`/`eslint`(기존 경고 2건 외 신규 없음)/`vitest run`(137 tests 통과)/`npm run build` 통과(빌드 후 `dist/` 삭제해 로컬 개발 백엔드 정적 서빙 오작동 방지). vite 재기동(WSL DrvFs 캐시 이슈로 `node_modules/.vite` 삭제 + `--force`) 후 Playwright로 실제 브라우저 E2E: 비로그인 상태에서 포메이션 선택·피치 렌더링·저장 버튼 비활성화 확인 → 회원가입(클라이언트 사이드 네비게이션으로, 전체 새로고침 없이) → 헤더에 이메일 표시·저장 버튼 즉시 활성화 확인 → 저장 목록에서 기존 27건 전부 보임(첫 가입 귀속 확인) → 로그아웃 → 헤더가 로그인 링크로 복귀·저장 버튼 재비활성화·피치는 계속 렌더링(비로그인 편집 유지) 확인. 9개 체크 전부 통과. 테스트로 만든 계정·세션은 삭제하고 분석 소유권은 다시 NULL로 되돌려 실제 사용자의 첫 가입이 정상적으로 27건을 귀속받도록 정리함.
