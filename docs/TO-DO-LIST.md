### 33. GIF 내보내기가 끝없이 "만드는 중"에 멈추는 버그 수정

- **내용**: "gif내보내기 했는데 계속 만드는 중 이야" 리포트. Playwright로 그대로 재현 — 버튼이 "GIF 만드는 중…"에서 30초 넘게 안 바뀌었다(이전 세션과 달리 이번엔 데스크톱 Chromium에서도 100% 재현되는 버그였다).
- **원인**: 콘솔에 프레임마다 반복되는 에러 쌍을 확인했다 — `html-to-image`의 `toCanvas`가 캡처할 때마다 `embedWebFonts` 단계에서 문서의 모든 스타일시트의 `cssRules`를 읽으려 시도하는데, `index.html`에 Hallmark 리디자인(2026-09-11, 29번 항목) 때 추가한 Google Fonts `<link rel="stylesheet" href="https://fonts.googleapis.com/...">`가 **cross-origin**이라 `cssRules` 접근 자체가 브라우저 CORS 정책으로 막혀 `SecurityError: Failed to read the 'cssRules' property`가 매번 발생했다. GIF는 39프레임(`buildGifFrameSpecs`: 국면 3개 × (정지 1장 + 전환 보간 12장))을 순서대로 캡처하는데, 이 실패한 시도 하나가 프레임당 약 2초를 잡아먹어 **39장 전체가 70초 넘게 걸렸다** — "끝없이 멈춘" 게 아니라 극도로 느려진 것. PNG 내보내기(1회 캡처)는 같은 에러를 조용히 한 번만 겪고 넘어가서 눈에 안 띄었을 뿐 똑같이 느려지고 있었다.
- **수정**: `html-to-image`의 `toCanvas`/`toPng` 호출 3곳(`GifExportRunner.tsx`, `lib/exportImage.ts`의 `exportCard`·`captureThumbnail`) 전부에 `skipFonts: true` 옵션 추가 — 캡처는 이미 `document.fonts.ready`로 폰트가 로드·페인트된 같은 브라우저 탭 안에서 일어나므로, html-to-image가 폰트를 별도로 재다운로드해 SVG에 base64로 embed할 필요가 없다(embed는 SVG 마크업을 이 탭 밖에서 독립적으로 쓸 때만 의미가 있음). 이 단계를 건너뛰면 CORS 에러 자체가 안 나고, 시각적 결과물(이미 렌더링된 폰트 그대로 캡처)도 동일하다.
- **검증**: `tsc -b`/`npm run lint`(0 errors)/`vitest run`(174, 회귀 없음)/`npm run build` 통과. Playwright로 GIF 내보내기 재현 — 수정 전 30초 관찰 동안 한 번도 안 끝나던 게, 수정 후 **4초 만에** 버튼이 "GIF 내보내기"로 돌아오고 다운로드가 트리거됨을 확인, 콘솔에 CORS `SecurityError`가 더 이상 안 뜨는 것도 확인.
- **추가 확인**: Playwright로 실제 다운로드된 GIF 파일을 저장해 육안으로 열어봄 — 제목이 Nanum Gothic Coding, 본문이 IBM Plex Sans KR로 정상 렌더링되고 폰트 폴백으로 인한 간격 깨짐(이전 세션에서 잡았던 버그) 없이 나온 것을 확인. GIF 전체 재생(프레임 간 애니메이션)까지는 정적 이미지 뷰어로 확인이 안 돼 이 부분만 사용자 확인이 남는다.
- **미확인**: 여러 프레임에 걸친 실제 재생(모프 애니메이션이 자연스럽게 이어지는지)은 GIF를 재생 가능한 뷰어로 열어야 확인되므로 사용자가 봐줘야 한다.

### 34. 프리셋 선수 이름 한국어 표기 전수 조사·수정 + 피치 선수 이름 폰트 명시

- **내용**: "감독들 프리셋에 있는 선수들 이름 중에 잘못 표기된 애들이 있어. 예를 들면 제주슨데 예수스, 하베르츤데 하버츠처럼. 사람들이 주로 그렇게 안 부르니까 다시 한 번 인터넷에서 검색해서 조사하고 이름 다 한 번씩 체크하면서 수정해줘. 그리고 전술판에 있는 선수 이름들 폰트도 바꿔줘 지금 우리 쓰는 폰트로" — 두 가지 요청. 예시로 든 "제주스→예수스"·"하베르츠→하버츠" 자체는 실제로 찾아보니 이미 올바르게(하버츠·예수스) 들어가 있었다 — 순수 예시(이런 유형의 실수를 찾으라는 뜻)로 받아들이고 전체 프리셋(감독 10개 + 실제 경기 2개, 총 172명)의 이름을 전부 웹 검색으로 대조했다.
- **조사 방법**: 각 프리셋 JSON의 `players[].name`을 전부 추출해 목록화한 뒤, 극히 유명한 이름(메시·호날두급)은 표준 표기가 명백해 제외하고, 표기가 갈릴 수 있는 이름(복합 성·외래어 표기 세칙이 실제 통용과 다른 경우) 위주로 WebSearch로 다음스포츠·나무위키·위키백과·공식 구단 홈페이지 등의 실제 표기 빈도를 확인했다. **원칙**: 국립국어원 표기 규정보다 **실제로 한국 축구 팬·매체가 가장 많이 쓰는 표기**를 우선한다(사용자가 명시한 "사람들이 주로 그렇게 안 부르니까" 기준) — 예를 들어 홀란(Haaland)은 국립국어원 권고 표기지만 "홀란드"가 훨씬 더 널리 쓰여 후자를 택함.
- **수정(11건, 6개 파일)**:
  - `managers/guardiola.json`: 홀란→**홀란드**(국립국어원 권고보다 통용 표기 우선), 베르나르도 실바→**베르나르두 실바**(포르투갈어 표기 세칙상 어말 o는 '두')

- **피치 선수 이름 폰트 명시**: 확인해보니 선수 이름 SVG `<text>`는 별도 `font-family` 지정이 없어 `<body>`(IBM Plex Sans KR, Hallmark 리디자인 때 지정)를 상속해 Chromium에서는 이미 올바른 폰트로 보이고 있었다 — 다만 이번 세션에서 반복적으로 "헤드리스에선 되는데 실기기 Safari에서만 다르게 렌더링"되는 패턴이 나왔던 만큼(HTML→SVG 경계를 넘는 CSS 상속은 브라우저마다 다르게 동작할 수 있음), 암묵적 상속에 기대지 않고 **명시적으로** 지정하기로 했다. `lib/theme.ts`에 `PITCH_TEXT_FONT_FAMILY` 상수(IBM Plex Sans KR 스택, `tailwind.config.js`의 `fontFamily.sans`와 동일한 값) 추가 후, 선수 라벨을 그리는 4개 컴포넌트(`PlayerNode`·`PrintPlayerNode`·`SharePlayerNode`·`StaticPlayerNode`, 각각 편집기·GIF 캡처·공유 페이지·전술 대결 뷰 전용) 전부의 이름·등번호·포지션 라벨 텍스트(총 11곳)에 `style.fontFamily`로 명시 적용.
- **검증**: 수정한 JSON 6개 파일 전부 `python -c "json.load(...)"`로 유효성 확인. `tsc -b`/`npm run lint`(0 errors)/`vitest run`(174, `samples.test.ts`가 모든 프리셋을 스키마 검증 — 회귀 없음)/`npm run build` 통과. Playwright로 (1) 과르디올라 프리셋에서 "홀란드"·"베르나르두"가 실제 페이지 텍스트에 포함된 것 확인, (2) 피치 SVG의 선수 이름·등번호·포지션 라벨의 인라인 `style.fontFamily`와 `getComputedStyle().fontFamily`가 둘 다 `"IBM Plex Sans KR", ui-sans-serif, system-ui, sans-serif`로 일치하는 것 확인, (3) 스크린샷으로 "홀란드"·"포든"·"더 브라위너"·"도쿠" 라벨이 실제로 올바른 한글 폰트로 깨짐 없이 렌더링되는 것 육안 확인.
- **미확인**: 이름 표기는 웹 검색 기반 조사라 100% 확신은 아니다(특히 국립국어원 표기와 통용 표기가 갈리는 경우 "더 많이 쓰이는 쪽"이라는 사용자 지침을 따랐을 뿐 절대적으로 "정답"이 하나는 아님) — 사용자가 익숙한 표기와 다르면 알려달라. 실기기 Safari에서 피치 폰트가 의도대로 보이는지도 재확인이 필요하다.
