## 항목 상세

### 3. 감독 프리셋 추가

- **내용**: 후보 — 무리뉴, 안첼로티, 투헬, 포체티노 등 + K리그 감독. `frontend/public/samples/managers/`에 JSON 추가 + `ManagerPresetPicker` 배열 등록이 전부.
- **유의**: 좌표는 공개 전술 분석 기반 재구성(실제 트래킹 아님) — 기존 프리셋과 같은 주석 유지. 감독 최신 이력(해임·이적)은 추가 시점에 다시 확인한다.
- **사용자 요청(2026-09-07)**: "3번 감독 프리셋 추가하자"
- **구현**: 무리뉴·안첼로티·투헬 3명 추가(`mourinho.json`/`ancelotti.json`/`tuchel.json`). 지식 컷오프(2026-01) 이후 이적 가능성이 있어 착수 전 웹 조사 에이전트 3개를 병렬로 띄워 각자 현재 소속·실제 선발 라인업을 교차 확인 — 셋 다 지식 컷오프 이후 새 자리로 이동한 상태였다(무리뉴→레알 마드리드, 안첼로티→브라질 대표팀, 투헬→잉글랜드 대표팀, 둘 다 2026 월드컵 감독). 실제 확정 선발 XI·등번호를 기반으로 국면별 좌표를 재구성했고, 투헬 프리셋은 국면마다 포메이션이 크게 바뀌는 특징(공격 시 풀백 인버트로 사실상 3-2-5, 비보유 시 4-4-2)까지 좌표만으로 표현했다. `formation` 필드는 국면 내내 고정값(기존 프리셋들과 동일한 방식)이며 시각적 형태 변화는 좌표 이동만으로 구현.
- **검증**: `tsc --noEmit`/`eslint --max-warnings 0`(기존 경고 2건은 이번 변경과 무관)/`vitest run`(신규 3개 파일 모두 `samples.test.ts` zod 스키마 통과, 119 tests) 통과. `npm run build` 성공. vite 재기동 후 Playwright로 `/new`에서 3개 프리셋 모두 로드해 스크린샷 확인 — 포메이션 모양·등번호·포지션 라벨·패스 체인 연결·런 화살표 전부 의도대로 렌더링됨(기존 프리셋 대비 동일한 ellipse 개수로 렌더링 정상 확인).

### 5. 타임라인 (매치 체인징 포인트)

- **내용**: 3국면 고정을 넘어 경기 시간 축에 체인징 포인트를 여러 개 찍고 시점별 대형 저장. "전반 23분 추격 상황" 재현.
- **기술 메모**: 프론트 스토어·zod가 이미 대비함 — `convertKeys`가 `phases` 맵 키를 보호하는 이유가 이 확장이다(`api.ts` 주석 참조). 국면 키가 `base/attack/defense`에서 벗어나도 깨지지 않음. DB `phases.phase_type`은 문자열이라 호환. UI(타임라인 바)가 주 공수.
- **사용자 요청(2026-09-09)**: "다음 항목 시작해줘"(5번 차례) → 범위 확인 질문에 "기존 3국면에 추가(권장)" 선택 — base/attack/defense 3버튼은 그대로 두고, 그 옆에 별개의 선택적 타임라인을 추가하는 쪽으로 확정. 국면 전체를 자유 타임라인으로 교체하는 안은 채택하지 않음.
- **구현**:
  - **타입**: `ChangingPoint`(=`PhaseData` + `id`/`label`/`minute?`) 신규, `Analysis.changingPoints?: ChangingPoint[]`(선택 필드 — 구버전 데이터도 그대로 유효).
  - **스토어**: `selectedChangingPointId` 상태 추가. `movePlayer`/`moveOpponent`/`addAnnotation`/`removeAnnotation`/`addOpponents`/`addOpponentsFromFormation`/`removeOpponents`/`setPressingLineLevel`/`setComment` 8~9개 편집 액션을 "지금 보이는 곳"(체인징 포인트 선택 중이면 그곳, 아니면 `currentPhase`) 기준으로 일반화(`getActivePhaseData`/`withActivePhaseUpdate` 헬퍼). `addChangingPoint`는 지금 보이는 곳의 좌표를 복제해 새 포인트를 만들고 선택하되, 코멘트·화살표는 그 시점 고유 내용이라 비워서 시작. `switchPhase`(국면 탭 클릭)는 항상 체인징 포인트 선택을 해제 — 같은 국면을 다시 눌러도 해제되도록 조기 반환 조건 수정.
  - **UI**: `Timeline.tsx` 신규(국면 탭 바로 아래, 칩 목록 + "+시점" + 선택 중인 포인트의 이름 인라인 편집·좌우 이동·삭제). `PhaseTabs`는 체인징 포인트를 보는 동안 탭 3개 중 어느 것도 활성으로 표시하지 않음. `CommentPanel`은 `phase: PhaseType` 대신 `title`/`phasePositions`를 받도록 일반화(국면이든 체인징 포인트든 같은 컴포넌트 재사용).
  - **백엔드**: `phases`/`positions`/`annotations` 테이블을 그대로 재사용 — 체인징 포인트마다 전용 `Phase` 행(`phase_type="cp:<client_id>"`)을 만들고, 새 `changing_points` 테이블(라벨·순서·그 Phase 행 FK만 보관)이 메타데이터를 얹는다. 새 테이블이라 `create_all`이 자동 생성(ALTER TABLE 불필요). `AnalysisIn.changing_points: List[ChangingPointIn] = []`(없으면 빈 목록 — 구버전 클라이언트도 그대로 호환), player_id 참조·중복·id 중복 검증을 3국면과 동일하게 적용. PNG/GIF 내보내기는 이번 범위에서 제외(항상 `currentPhase` 기준 그대로) — 필요해지면 후속 작업.
  - **데모 예시(2026-09-09, 사용자 요청 "일부만 넣자, 타임라인 예시 느낌으로 2개만 넣자")**: 감독 프리셋 10종 중 2개(투헬·안첼로티)에 체인징 포인트 1개씩 추가. 둘 다 각 프리셋 `summary`에 이미 적어둔 실제 2026 월드컵 경기 결과에 근거한 "후반 막판 추격" 장면(투헬: 3·4위전 프랑스전 6-4 승리, 78분·안첼로티: 16강 노르웨이전 1-2 패배, 84분) — 실제 스코어와 어긋나지 않게 극단적인 올인 공격 대형(골키퍼까지 하프라인 근처로 전진)으로 구성. 나머지 8개 프리셋은 타임라인 없이 그대로 둠(선택 기능이라 스키마·기능에 영향 없음).
  - **시간(분) 필드 추가(2026-09-09, 사용자 요청 "타임라인이 나는 시간대도 있어야 할 것 같아")**: `ChangingPoint.minute?: number`(0~120, 연장전 포함). `Timeline.tsx`를 칩 목록에서 0~120분 시간축 바(0'/45'/90'/120' 눈금 + 전후반 종료선)로 교체 — minute이 있는 포인트는 그 위치에 점으로, 없는 포인트는 축 아래 "시간 미정" 칩으로 따로 모아 보여준다(구버전 데이터·시간을 아직 모르는 새 포인트도 그대로 유효). 선택된 포인트 패널에 분 입력 필드 추가, `setChangingPointMinute` 액션 신규. 백엔드는 `changing_points` 테이블에 `minute` 컬럼 추가 — 이 테이블 자체가 방금 전 커밋에서 이미 만들어졌으므로(기존 배포에 이미 존재할 수 있음) `tactical_role`/`curved`와 같은 `_ensure_column` ALTER TABLE 패턴으로 안전하게 채운다.
- **검증**: `tsc -p tsconfig.app.json --noEmit`/`eslint --max-warnings 0`(기존 경고 2건은 무관)/`vitest run`(스토어에 타임라인 전용 테스트 9개, 총 128 tests, `analysisSchema` 라운드트립 + 구버전 호환 케이스 포함) 통과. `npm run build` 성공. 백엔드는 별도 스크래치 SQLite로 실제 서버를 띄워 `POST`(생성)→`GET`(재조회)→`PUT`(교체)→`DELETE`(cascade) 전 과정을 curl로 확인 — 체인징 포인트가 정확히 저장·복원되고, `phases` 응답에는 내부 `cp:` 행이 노출되지 않으며, 삭제 시 `changing_points`/`phases`/`positions`/`annotations` 전 테이블이 고아 행 없이 깨끗이 지워짐을 raw SQLite 카운트로 확인. `minute` 컬럼은 컬럼 없는 예전 스키마의 `changing_points` 테이블을 수동으로 만든 뒤 서버를 띄워 `_ensure_column`이 실제로 `ALTER TABLE`을 실행하는지, 그리고 minute 있는/없는 두 체인징 포인트가 각각 올바르게 저장·조회되는지 확인. 프론트는 vite 재기동(포트 충돌로 5174 별도 인스턴스 사용) 후 Playwright로 추가→탭 비활성화 확인→이름 변경→드래그로 좌표 수정(해당 포인트에만 반영, `base` 국면은 그대로)→국면 탭 복귀 시 선택 해제→재선택 시 수정 내용 유지→코멘트 패널 제목 반영→삭제, 그리고 시간축 점 클릭 선택→분 입력으로 "시간 미정"에서 축 위로 이동까지 전 플로우 확인.

### 7. 분석 목록 고도화

- **내용**: 목록 화면에 썸네일 미리보기(base 국면 미니 렌더링), 제목·날짜 검색, 태그. 목록이 수십 개가 되면 필요.
- **기술 메모**: 썸네일은 저장 시점에 base 국면을 작은 PNG로 만들어 두는 방식(목록 조회 시 렌더링은 느림) — 백엔드에 파일 또는 BLOB 컬럼 필요.

### 8. 공유 링크

- **내용**: 저장된 분석의 읽기 전용 URL. 로그인 없이 열람만.
- **기술 메모**: 공개 배포 + 공개 조회 API 필요. 데이터가 공개된다는 점 사용자 동의 필요.

### 9. 실제 경기 명장면 프리셋 (StatsBomb OpenData)

- **내용**: 원래 원했던 "실제 경기 분석"의 부분 실현. StatsBomb OpenData(무료, GitHub 공개)의 이벤트 데이터에는 슈팅 순간 양 팀 전원의 실제 좌표(freeze frame)가 담겨 있어, 이를 국면 프리셋으로 변환하면 "2022 월드컵 결승 결승골 장면" 같은 실제 배치를 불러올 수 있음.
- **제약 (중요)**: 슈팅 장면 위주(전 경기 트래킹 아님), 좌표계 변환(StatsBomb는 0~120 × 0~80) 필요, 원본 JSON이 커서 사전 가공 스크립트 필요. 작업량 중~대.
- **연혁**: "실제 경기를 DB에서 검색해 자동 분석"은 2026-09-01 무료 API가 국면별 선수 좌표를 제공하지 않아 기각 → 감독 프리셋으로 대체. 이 항목은 그 대안의 확장.

### 10. 배포 (Docker)

- **내용**: 저장소 루트의 `Dockerfile`/`docker-compose.yml`(백엔드 이미지 + `./data` 볼륨 마운트)은 이미 존재. 남은 결정: 프론트 빌드 산출물을 백엔드 이미지에 정적 서빙으로 포함할지 별도로 둘지.
- **기술 메모**: 컨테이너에서 `npm run build` → FastAPI가 `dist/`를 StaticFiles로 서빙하는 단일 이미지 구성이 가장 단순. 개발은 계속 로컬 2프로세스.

### 11. 로그인/계정

- **내용**: 분석 목록을 사용자별로 분리. 로컬 1인용인 동안은 의미가 제한적이라 배포 이후로 미룸.

### 12. 커뮤니티/댓글

- **내용**: 공유된 분석에 의견. 로그인·배포 이후의 마지막 단계.
