# TactiCraft 사용성·기술·기능 개선 로드맵

> 작성일: 2026-09-18
> 작성자: 사용자(카카오톡으로 전달받은 분석 문서를 그대로 편입)
> 목적: 현재 MVP의 장점을 유지하면서 사용자가 더 안심하고 쉽게 반복 사용할 수 있는 제품으로 발전시키기 위한 개선 방향을 정의한다.

## 1. 문서 개요

TactiCraft는 포메이션 선택부터 전술 편집, 저장, 공유, 커뮤니티, 전술 대결까지 하나의 제품 흐름을 이미 갖추고 있다. 프런트엔드의 전술 계산 로직과 단위 테스트도 비교적 충실하다.

다음 단계에서는 기능 수를 단순히 늘리기보다 아래 세 가지 문제를 먼저 해결한다.

1. 사용자가 작성 중인 전술을 잃지 않게 한다.
2. 비공개와 공개의 의미를 사용자가 믿을 수 있게 한다.
3. 많은 기능을 처음 사용하는 사람도 순서대로 익힐 수 있게 한다.

이 문서는 제품·사용성 관점과 기술·운영 관점의 독립 검토 결과를 종합했다. 두 관점이 합의한 내용과 의견이 다른 내용을 구분하고, 실제 작업 순서를 제안한다.

## 2. 현재 강점

- 프리셋 → 편집 → 저장 → 공유 → 커뮤니티 → 전술 대결로 이어지는 제품 흐름이 있다.
- 포메이션, 좌표, 콤팩트니스, 수적 우위, 매치업 계산이 UI와 분리돼 있다.
- 프런트엔드 단위 테스트가 전술 계산의 경계값과 예외 상황을 폭넓게 다룬다.
- API 입력에서 선수 수, 좌표 범위, 중복 ID, 국면 간 일관성을 검증한다.
- 비밀번호 해시, HttpOnly 세션 쿠키, 분석 수정·삭제 소유권 검사 등 기본 보안 장치가 있다.
- 모바일 레이아웃, 서버 중단 상태, 빈 화면, 로딩 상태 등 MVP 이상의 상태 처리가 구현돼 있다.

개선 과정에서는 이 기반을 다시 만드는 대규모 재작성보다, 신뢰성과 발견 가능성을 보강하는 방식을 우선한다.

## 3. 핵심 원칙

### 3.1 신뢰가 기능 수보다 우선한다

새로운 전술 지표보다 초안 복구, 접근 권한, 백업, 테스트가 우선이다. 사용자가 작업을 잃거나 비공개 전술이 노출되면 다른 기능의 가치도 함께 떨어진다.

### 3.2 초보자와 숙련자를 같은 화면에 억지로 맞추지 않는다

핵심 기능은 바로 보이게 하고, 타임라인 병합이나 고급 레이어는 필요할 때 펼쳐 쓰게 한다.

### 3.3 자동화는 되돌릴 수 있어야 한다

로컬 초안은 자동 저장하되 서버 저장은 당분간 명시적으로 수행한다. 서버 자동 저장은 버전 기록과 충돌 처리가 준비된 뒤 검토한다.

### 3.4 전술 지표는 계산 근거와 한계를 설명한다

좌표 기반 보조 지표를 승률이나 객관적인 전술 우열처럼 표현하지 않는다. 사용자가 계산 방식과 해석 범위를 확인할 수 있어야 한다.

## 5. P0: 신뢰성과 데이터 보호

### 5.1 초안 자동복구와 이탈 방지

#### 현재 문제

- 편집 상태가 브라우저 메모리에만 있다.
- 미저장 경고가 로고 클릭에만 적용된다.
- 다른 메뉴 이동, 새로고침, 탭 종료 시 작업을 잃을 수 있다.
- 비로그인 편집이 가능하지만 서버 저장은 로그인 후에만 가능하므로 임시 저장의 필요성이 크다.

#### 개선안

- 편집 내용을 3~5초 debounce로 브라우저에 임시 저장한다.
- 재접속 시 `복구할 초안이 있습니다` 안내와 `복구하기 / 버리기`를 제공한다.
- 메뉴 이동, 새 분석 불러오기, 새로고침, 탭 종료 전에 미저장 상태를 확인한다.
- 저장 상태를 `변경됨 / 임시 저장됨 / 서버 저장됨 / 저장 실패`로 구분한다.
- 서버 저장에 실패해도 현재 편집 내용과 로컬 초안은 유지한다.
- 서버 저장 성공 후 해당 로컬 초안을 정리한다.

#### 완료 기준

- 새로고침 후 작성 중인 전술을 복구할 수 있다.
- 어떤 상단 메뉴를 눌러도 미저장 변경이 조용히 사라지지 않는다.
- 서버가 중단돼도 편집과 로컬 복구가 가능하다.

### 5.2 공개 범위 모델 재설계

#### 현재 문제

`is_public=false`인 분석도 순차 숫자 ID를 알면 비로그인 상태에서 조회할 수 있다. 현재 `커뮤니티 공개`는 커뮤니티 목록 노출 여부만 제어하며, 분석 자체의 읽기 권한은 제어하지 않는다.

#### 개선안

분석의 공개 범위를 다음 세 단계로 나눈다.

| 공개 상태 | 접근 가능 대상 | 목록 노출 | 댓글·좋아요 |
| --- | --- | --- | --- |
| 비공개 | 소유자만 | 없음 | 없음 |
| 링크 공개 | 무작위 공유 토큰을 가진 사용자 | 없음 | 소유자 설정에 따름 |
| 커뮤니티 공개 | 누구나 | 커뮤니티에 노출 | 허용 |

- 공유 URL은 순차 ID 대신 예측 불가능한 토큰을 사용한다.
- 공유 링크 재발급과 폐기를 지원한다.
- 댓글 허용 여부와 복제 허용 여부를 소유자가 선택할 수 있게 한다.
- UI에서 각 공개 상태의 의미를 짧고 명확하게 설명한다.
- 기존 분석에 대한 마이그레이션 정책을 별도로 정한다.

#### 완료 기준

- 비공개 분석은 비로그인 사용자와 다른 회원이 조회할 수 없다.
- 링크 공개 분석은 올바른 토큰이 없으면 조회할 수 없다.
- 커뮤니티 공개 분석만 커뮤니티 검색과 정렬에 노출된다.
- 각 권한 조합에 대한 API 자동 테스트가 있다.

### 5.3 백엔드 테스트와 CI 품질 게이트

#### 필수 백엔드 테스트

- 회원가입, 로그인, 로그아웃
- 세션 만료와 무효화
- 회원 A가 회원 B의 분석을 조회·수정·삭제할 수 없는지 확인
- 비공개·링크 공개·커뮤니티 공개 권한 확인
- 저장 후 재조회했을 때 선수 좌표와 전술 데이터가 동일한지 확인
- 댓글·좋아요·공개 전환 권한 확인
- 회원 탈퇴 시 관련 데이터 처리 확인
- 잘못된 좌표, 선수 수, 중복 ID 요청 거부 확인

#### CI 실행 순서

```text
프런트 lint
→ 프런트 단위 테스트
→ 프런트 프로덕션 빌드
→ 백엔드 테스트
→ 배포
```

어느 단계라도 실패하면 배포하지 않는다.

### 5.4 DB 마이그레이션·백업·복구

- 앱 시작 시 직접 실행하는 `ALTER TABLE`을 Alembic 마이그레이션으로 전환한다.
- 배포 전에 자동 백업을 생성한다.
- 정기 스냅샷과 보관 정책을 정한다.
- 백업 파일을 실제로 복원하는 리허설을 수행한다.
- health check가 서버 프로세스뿐 아니라 DB 읽기까지 확인하게 한다.
- 배포 실패 시 이전 이미지와 DB 버전으로 되돌리는 절차를 문서화한다.

SQLite는 현재 규모에서 유지한다. PostgreSQL 전환은 동시 쓰기 지연이나 다중 인스턴스 요구가 실제로 발생할 때 검토한다.

### 5.5 공개 서비스 보호

- 로그인과 회원가입에 IP·계정별 요청 제한을 적용한다.
- 댓글, 좋아요, 반응 API에 요청 제한을 적용한다.
- 세션에 `expires_at`과 마지막 사용 시각을 추가한다.
- 세션 토큰은 원문 대신 해시로 저장한다.
- 만료 세션을 정기적으로 정리한다.
- 썸네일, 요약, 태그, 화살표, 타임라인 시점 수와 요청 본문 크기에 상한을 둔다.
- CSP, `X-Content-Type-Options`, `Referrer-Policy` 등 보안 헤더를 설정한다.
- 신고·숨김·차단과 최소한의 운영자 처리 수단을 마련한다.

### 5.6 Fly.io 콜드 스타트 대응

현재 서버 자동 정지 설정과 2초 health check가 충돌할 수 있다. 서버가 잠든 상태에서 health check가 먼저 실패하면 저장 버튼이 비활성화될 수 있다.

- health check 실패만으로 저장 버튼을 영구 비활성화하지 않는다.
- 실제 저장 요청을 통해 서버를 깨울 수 있게 한다.
- `서버 깨우는 중 → 재시도 중 → 저장 완료` 상태를 보여준다.
- 더 긴 타임아웃과 제한된 백오프 재시도를 적용한다.

## 6. P1: 일상 사용성 개선

### 6.1 최초 사용자 가이드와 점진적 공개

처음 사용하는 사용자를 다음 네 단계로 안내한다.

1. 선수를 움직여 기본 배치를 만든다.
2. 패스와 선수 움직임을 그린다.
3. 공격·수비 국면을 작성한다.
4. 저장하고 공유한다.

타임라인 병합, 콤팩트니스, 오버로드, 압박선 등은 `고급 기능` 영역에 배치한다. 사용자가 기능을 처음 펼쳤을 때만 짧은 설명을 제공한다.

### 6.2 모바일 핵심 여정 개선

- 모바일 하단 `PNG 내보내기`가 실제 내보내기를 수행하게 한다.
- 즉시 내보내기가 어렵다면 버튼명을 `내보내기 설정으로 이동`으로 바꾼다.
- 하단 시트에서 비율을 선택하고 바로 PNG를 생성할 수 있게 한다.
- 저장 버튼과 썸네일 캡처 상태를 하나의 command/state로 통합한다.
- 저장 목록은 모바일에서 썸네일·제목·경기·날짜·태그·공개 상태를 담은 카드로 표시한다.
- 생성 → 편집 → 로그인 → 저장 → 공유의 모바일 E2E 테스트를 추가한다.

### 6.3 성공·실패 피드백 통일

전역 toast와 `aria-live`를 사용해 다음 상태를 일관되게 알린다.

- 저장 완료와 실패
- 임시 저장 완료
- 링크 복사 완료
- 공개 상태 변경
- 분석 복제와 삭제
- 서버 재시도
- 로그인 필요
- 저장 충돌

로그인이 필요한 작업에서는 현재 편집 내용을 보존하고 로그인 후 원래 화면으로 돌아오게 한다.

### 6.4 접근성

- 선수와 상대 선수 노드에 키보드 포커스와 의미 있는 `aria-label`을 제공한다.
- 방향키로 미세 이동, `Shift + 방향키`로 큰 이동을 지원한다.
- 현재 선수명과 좌표를 스크린리더에 전달한다.
- 반복 애니메이션은 `prefers-reduced-motion`을 존중한다.
- 범위 입력과 아이콘 버튼에 명확한 label을 제공한다.
- 404 화면과 전역 error boundary를 추가한다.
- 주요 키보드 단축키 도움말을 제공한다.

## 7. P1: 반복 사용 가치를 높이는 기능

### 7.1 버전 기록과 충돌 처리

- 저장 시 얇은 revision snapshot을 생성한다.
- `전반 시작`, `후반 수정`, `상대 압박 대응`처럼 버전명을 붙일 수 있게 한다.
- 최근 버전을 비교하고 복원할 수 있게 한다.
- 저장 요청에 revision을 포함하고 오래된 revision으로 저장하면 `409 Conflict`를 반환한다.
- 충돌 시 `최신본 보기 / 내 변경을 복사본으로 저장 / 변경 비교`를 제공한다.

### 7.2 내 팀·선수단 템플릿

- 팀명, 선수명, 등번호, 포지션, 역할을 템플릿으로 저장한다.
- 새 분석을 만들 때 저장된 선수단을 불러올 수 있게 한다.
- 템플릿 수정이 기존 분석을 임의로 변경하지 않게 한다.

### 7.3 커뮤니티 리믹스

공개 전술을 내 분석으로 복제하되 다음 정보를 보존한다.

- 원작자
- 원본 분석 링크
- 복제 시점
- 원작자의 복제 허용 여부

이를 통해 커뮤니티의 열람이 새로운 전술 제작으로 이어지는 순환을 만든다.

### 7.4 전술 대결 진입 개선

- 저장 목록과 커뮤니티 카드에 `비교하기`를 제공한다.
- 첫 번째 전술을 고정한 뒤 두 번째 전술을 선택하게 한다.
- 같은 분석을 A와 B에 동시에 선택하지 못하게 한다.
- 최근 비교 기록과 비교 설정 프리셋을 제공한다.

### 7.5 전술 지표 설명

- 수적 우위, 콤팩트니스, 폭·깊이, 병목의 계산 근거를 표시한다.
- 자동 제안이 어떤 좌표와 규칙을 사용했는지 설명한다.
- 지표가 실제 경기 결과나 승률을 보장하지 않는다는 한계를 명시한다.
- 설명할 수 없는 단일 종합 점수는 추가하지 않는다.

## 9. 서로 다른 의견과 최종 방향

| 쟁점 | 제품·UX 관점 | 기술·운영 관점 | 최종 방향 |
| --- | --- | --- | --- |
| 첫 작업 | 작업 유실과 편집 복잡도부터 해결 | 권한·테스트·DB 안전성부터 해결 | 초안 복구와 권한을 함께 P0로 진행한 뒤 CI·DB 적용 |
| 저장 방식 | 사용자가 저장을 거의 의식하지 않게 함 | 서버 자동 저장은 충돌과 잘못된 변경도 확정할 수 있음 | 로컬 자동복구 + 명시적 서버 저장부터 시작 |
| 공개 설정 | 최대한 단순한 UI가 중요 | 3단계 권한 구분이 필수 | UI는 단순하게, 내부 모델은 3단계로 설계 |
| 신규 커뮤니티 기능 | 리믹스와 발표 모드가 제품 순환을 강화 | 신고·rate limit·권한이 먼저 | 운영 안전장치 후 리믹스, 발표 모드는 다음 단계 |

| PostgreSQL | 당장 사용자 가치가 없음 | 장기적으로 필요할 수 있음 | SQLite 유지, 실제 병목이 생길 때 전환 |
| 전술 점수 | 이해를 돕는다면 확장 가능 | 설명 불가능한 종합 점수는 오도 위험 | 근거와 한계를 설명할 수 있는 지표만 추가 |
| 완전 오프라인 | 장기적으로 매력적 | 동기화와 충돌 해결 비용이 큼 | 우선 로컬 초안 복구만 적용 |
| 실시간 공동 편집 | 협업 기능으로 매력적 | 현재 기반에서는 위험과 비용이 큼 | 버전·충돌·권한 체계 이후 P2로 보류 |

## 12. 최종 결론

TactiCraft의 다음 목표는 기능이 더 많은 전술판이 아니라 다음 조건을 만족하는 신뢰할 수 있는 전술 작업 공간이다.

- 내 작업이 사라지지 않는다.
- 누가 내 전술을 볼 수 있는지 분명하다.
- 처음 사용하는 사람도 순서대로 익힐 수 있다.
- 문제가 생겨도 이전 상태로 복구할 수 있다.
- 전술 지표의 의미와 한계를 이해할 수 있다.

따라서 다음 개발은 **작업 복구와 접근 권한 → 테스트·배포·백업 → 편집 사용성 → 버전·리믹스·발표 기능** 순서로 진행한다.
